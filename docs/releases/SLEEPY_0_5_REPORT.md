# Sleepy 0.5 — отчёт о реализации

Дата: 25.11.2026  
Ветка: `master`  
Базовая точка: `77fe940`  
Статус: изменения не закоммичены и не отправлены в удалённый репозиторий.

## Итог

Sleepy 0.5 собран как локальное Android-приложение для мониторинга сна:

- главный экран с запуском и завершением мониторинга;
- запись только звуковых событий, без непрерывной ночной записи;
- хранение сессий, отчётов, оценок и звуковых событий на устройстве;
- история ночей и аналитика;
- удаление отдельных WAV-фрагментов;
- обычный и «умный» будильник с нативным планированием Android;
- пять основных разделов: «Главная», «Анализ», «Звуки», «История», «Настройки».

## Что реализовано

### Навигация и интерфейс

- `MainScreen` переведён на пять вкладок.
- Главный экран показывает приветствие, статус мониторинга, длительность, события, сохранённые WAV, последнюю ночь, краткую статистику и ближайший будильник.
- Экран записи показывает состояние микрофона, foreground-службы, длительность и последние фрагменты.
- Настройки показывают статус мониторинга, разрешение точного будильника, локальное хранение и ограничения данных.
- Добавлены общие компоненты интерфейса: карточки, метрики, статусы, пустые состояния, уведомления.

### Сон, оценка и отчёты

- Сессия сна создаётся при старте мониторинга и завершается при остановке.
- Активная сессия сохраняется, чтобы приложение могло восстановить состояние после перезапуска.
- Оценка 0–100 учитывает длительность 7–9 часов и регулярность; звуковые события показываются отдельно и не превращаются в оценку глубины.
- Глубина и эффективность не выдумываются: без EEG/PSG они остаются недоступными.
- Регулярность рассчитывается только при наличии минимум трёх ночей.
- Предварительная оценка явно помечается как provisional.
- Отчёт содержит распределение событий по часам, сравнение с предыдущей ночью и средним за семь ночей, рекомендации и пояснение об отсутствии клинической точности.
- История показывает завершённые и прерванные сессии.
- Аналитика показывает динамику оценок, длительность и события.

### Звуковые события

- Используется существующий аудиоконвейер: PCM 16 kHz, mono, 16 бит, WAV-фрагменты и metadata sidecar.
- Второй механизм записи не создавался.
- Экран «Звуки сна» показывает фрагменты, время, длительность и размер.
- Добавлено удаление WAV-фрагмента вместе с metadata sidecar.
- Удаление ограничено каталогом записей.
- В интерфейсе разделены обнаруженное событие и неподтверждённый тип звука.
- Классификатор не обучен и не используется.

### Будильник

- Реализованы модели, хранение, расчёт следующего срабатывания, включение и выключение.
- Поддерживаются ежедневные и выбранные дни недели, одноразовые будильники, громкость и «умное» окно.
- «Умное» окно сохраняется, но сейчас не выбирает момент по аудиоданным: сигнал срабатывает в обязательное время.
- Точное срабатывание выполняется через `AlarmManager.setAlarmClock`.
- При отсутствии разрешения на точный будильник используется безопасный inexact fallback с предупреждением.
- Из интерфейса можно открыть системный экран разрешения точных будильников.
- Одноразовый будильник после срабатывания удаляется из нативного хранилища.
- Повторяющийся будильник переносится на следующее срабатывание.
- Просроченный одноразовый будильник при загрузке отключается и отменяется.
- После перезагрузки устройства будильники восстанавливаются через `BootReceiver`.
- Для воспроизведения используется foreground-служба с типом `mediaPlayback`, WakeLock и выбранный системный сигнал будильника или уведомления.
- При возврате приложения из фона список будильников перезагружается.

### Локальное хранение

- Добавлен Dart-интерфейс локального key-value хранилища.
- Реализовано версионированное JSON-хранилище с резервной копией.
- Нативная реализация хранит данные в файлах приложения и пишет атомарно через временный файл.
- Поддерживаются ключи сессий, активной сессии и будильников.
- Данные не отправляются в сеть.

### Android

- Добавлены каналы `storage` и `alarm`.
- В канал записи добавлена операция удаления фрагмента.
- Добавлены разрешения для точного будильника, boot-receiver и media playback foreground-службы.
- Зарегистрированы сервис будильника и broadcast-receiver'ы.
- Реализованы `SleepyLocalStore`, `AlarmSpec`, `AlarmScheduleCalculator`, `SleepAlarmScheduler`, `SleepAlarmReceiver`, `AlarmPlaybackService` и `BootReceiver`.

## Ограничения

- Нет валидированного классификатора звуков. Тип события не определяется.
- Оценка сна не является медицинской или клинической.
- Нет EEG/PSG, поэтому глубина и эффективность не рассчитываются.
- Установка и запуск на реальном устройстве проверены; сценарии записи, точного будильника, inexact fallback и перезагрузки ещё не проверены.
- Не проверены MIUI/POCO, закрытие приложения системой, boot-reschedule и поведение foreground-службы.
- При inexact fallback система может сдвинуть время сигнала.
- Разрешение на уведомления запрашивается вместе с доступом к микрофону; если пользователь создаёт будильник без запуска записи, уведомление службы может быть скрыто.
- Версия в `pubspec.yaml` не менялась и остаётся `1.0.0+1`; 0.5 — продуктовая веха.

## Следующие шаги
